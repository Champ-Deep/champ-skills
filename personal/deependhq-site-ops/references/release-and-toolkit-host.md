# Releasing a branch to deependhq.com, and the toolkit host

## Custom domains: list all of them
`wrangler deploy` replaces the Worker's entire custom-domain set. `wrangler.jsonc` `routes` must list `deependhq.com`, `www.deependhq.com` and `toolkit.deependhq.com` (all `custom_domain: true`). A list with only the toolkit host would detach the apex and www and take the site down. After every deploy, confirm via the CF API `/accounts/<id>/workers/domains` that all three map to service `deependhq` (assistant.deependhq.com belongs to `deependhq-assistant`).

## Deploy path
Workers Builds deploys `main` on push. For a big release, deploy yourself first from the release worktree (`npx wrangler deploy --message ...`), smoke-test prod, then push `main` (Builds redeploys the same commit). Record the live version first with `npx wrangler deployments status --name deependhq` so `wrangler rollback <id>` is ready. `versions list` also shows preview uploads from branch pushes; only `deployments status` tells you what is live.

## The vault worktree overwrites main every night
`scripts/publish.sh` rsyncs `/Users/deep/Celsus/Efforts/Active/TheDeepEndHQ/deependhq-site` over a fresh clone of main with `--delete`. After any out-of-band merge to main: back up the vault folder, `git archive HEAD | tar -x` into a temp dir, rsync it into the vault folder (no --delete), delete from the vault any file the release deleted (`git diff --name-only --diff-filter=D`), run `npm ci` there (new deps such as react, motion, @clerk/backend), then `npm run build`, link-check and `npm test` in the vault. Diff vault against the archive: only build timestamps, `scripts/.entry-*`, `pending-entry.json`, `.weekly-publish.mjs`, `_to_delete` may differ. Never run git inside the vault folder.

## Merging generated pages
Prerendered HTML (`index.html`, `post/*/index.html`, `company/*`, `writing.html`...) is regenerated by `npm run build` (prepare-shells, build-data, prerender, islands). Resolve conflicts in generated HTML by taking either side, then rebuild; resolve only source files (`*.jsx`, `*.css`, `scripts/*.mjs`, `content.json`) by hand.

## Local testing
- `wrangler dev` rewrites the request host, so the toolkit route table never triggers with a Host header. Use `npx wrangler dev --local --port <p> --host toolkit.deependhq.com` for the toolkit host and a second instance without `--host` for the apex.
- Apply `npx wrangler d1 migrations apply toolkit-db --local` first or `/api/toolkit/config` returns 500 internal.
- Local assets dir is `.` so some requests stall 10 to 40 s in miniflare; give Playwright a 120 s timeout. This is not a production issue.
- Port 3177 is often taken by another session's server: check `lsof -nP -iTCP:<port> -sTCP:LISTEN` before trusting a response. `toolkit-integrated.browser.py` takes `WORKER_BASE`.

## Chatbot check
The Ask Deep widget is `https://assistant.deependhq.com/static/widget.js` and its launcher is `#dh-assistant-btn`. A real check clicks it in Playwright on production and confirms that the widget-config, healthz and conversations calls return 200 and that the panel opens with an input. Locally it fails CORS, so prove it on prod.

## Toolkit go-live state
D1 `toolkit-db` (78b99395-186d-44f5-854d-94aa85530f04) is bound as `TOOLKIT_DB` and migrated. Until Clerk keys and provider keys are set as Worker secrets, `/api/toolkit/config` returns `configured:false` and the toolkit shows "Setup needed". That is the correct fail-closed state, not a bug.

## Clerk production (ToolKit app, live since 2026-10-28)
- App `app_3L6R5PZikLJFYyRAruI825weYnm` ("ToolKit"), production instance on deependhq.com, FAPI `clerk.deependhq.com`. The DNS CNAMEs (clerk, accounts, clkmail, clk._domainkey, clk2._domainkey) are DNS only, not proxied. The wrangler OAuth token has no DNS scope; edit DNS through the Cloudflare connector EXECUTE tool.
- The Clerk MCP strips secret keys. Use `clerk env pull --app <id> --instance prod --file <0600 scratch file>`, pipe each value into `wrangler secret put`, and delete the file only after both report Success.
- `wrangler secret put` fails with "latest version isn't currently deployed" when a branch push left a newer preview upload. Redeploy main first, then set the secret.
- `/api/toolkit/config` reports configured only when `CLERK_JS_URL` is set. It is pinned in wrangler.jsonc vars to clerk-js 5.128.1. v6 splits out @clerk/ui, so don't bump it blindly.
- Password sign-in has device trust on, so a new browser gets an email code (`#/factor-two`). For a production smoke test, create a throwaway user through the Backend API with `bypass_client_trust: true` and a User-Agent header (Cloudflare returns 1010 to the default urllib UA), sign in through the real page, then DELETE the user. Script: ~/.hermes/cache/scratch/clerk_e2e.py (API, quote, admin denial) and clerk_drag_e2e.py (Matrix theme computed colours, window drag, icon drag persisted per user id, desktop CSV drop opens the Workbench, phone sign-in).
- On production, Playwright `page.wait_for_function("...string...")` fails because the toolkit CSP has no unsafe-eval. Wait with `page.locator('#daily', has_text='$').wait_for()` instead.
- Credits live in remote D1 `toolkit_settings`: default_daily_credit_cap 1000 ($1/day), welcome_credits 2000, trial_pool_credits 200000, global_daily_cap_micro 25000000, default_daily_row_cap 1000. Each smoke-test user consumes a $2 welcome grant from the pool.
